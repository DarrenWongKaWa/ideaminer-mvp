# InsightRecoder v0.7 — Insight Pool (multi-user via GitHub Issues)

## Goal

Bring back the v0.5.x "我写完能 share / 看到别人写的" multi-user
flow as an OPT-IN extension of v0.6. Local-first stays the default;
the Pool is a layer on top.

## Why GitHub Issues as the backend

- The project already lives on GitHub. No new auth surface.
- A public repo's issues are readable without any auth, so the
  "browse pool" UX is zero-config. To publish / like you need a
  GitHub PAT (fine-grained, issues: write only).
- Issues map cleanly onto "insights":
  - title    → short label / question (e.g. "Twisted MoS2 θ ≈ 1.08°")
  - body     → the full inspiration text
  - labels   → tags (lowercase, max 5)
  - reactions → likes (👍 +1, 👎 -1)
  - comments  → discussion thread per insight (future)
- The community decides the pool — a teacher sets up a class
  repo, friends share a private repo, an open lab uses a public
  one. Many pools, one app.

## Data model

The local-first store keeps everything it had in v0.6.2. The
Pool layer adds:

```js
// New in js/pool.js
class GitHubIssuePool {
  constructor({ owner, repo, token, baseUrl = 'https://api.github.com' })

  // Read (no auth required for public repos)
  async fetchAll({ since, perPage = 50 } = {})
    // returns [{number, title, body, labels, reactions, author,
    //          createdAt, updatedAt, _source: 'pool'}]

  // Auth-required
  async publish(inspiration)
    // Creates an issue. Returns {number, url, html_url}.
  async react(number, content)
    // content: '+1' (like) or '-1' (dislike) or 'eyes' etc.
  async unreact(number, content)

  // Local cache (so the Pool tab works offline after first load)
  cache: Map<number, PoolInspiration>   // in-memory only
  lastSync: number
}
```

Pool inspirations look like the local `Inspiration` type but
with extra fields:
```js
{
  id: 'pool-123',            // 'pool-' + issue number
  text: 'Twisted MoS2 at 1.08°',
  createdAt: <ts>,
  tags: ['materails', 'graphene'],
  source: 'pool',
  origin: { owner: '...', repo: '...', number: 123, htmlUrl: '...' },
  author: { login: 'darrenwongkawa', avatar: '...' },
  reactions: { '+1': 5, '-1': 1, 'laugh': 0, ... },
  myReaction: '+1' | null,
  isLocal: false,
}
```

## New Storage methods

```js
// In js/storage.js — keeps the local-first surface intact.
getPoolConfig() → {owner, repo, token} | null
setPoolConfig({owner, repo, token}) → void
getPoolCache() → PoolInspiration[]
setPoolCache(list) → void
getReactions() → Record<number, '+1' | '-1' | null>   // local override
setReaction(number, content) → void
```

The `getReactions` map is the "my reaction" overlay so the
user's like state survives even if the GitHub issue is briefly
unavailable (e.g. API rate-limited).

## UI changes

1. **Settings → Pool** (new sub-section):
   - If no config: a "Connect a GitHub pool" form with
     `owner / repo / token` (token stored in localStorage with
     a clear "this is a personal access token" warning and a
     link to the GitHub PAT creation page with `issues: write`
     pre-selected).
   - If configured: show the repo, a "Sync now" button, a
     "Disconnect" link.

2. **`/capture` → "Push to Pool" toggle** (new):
   - When the Pool is configured, a checkbox next to the Save
     button: "Also publish to <owner>/<repo>". Default OFF
     (local-first stays the default).
   - On save with the toggle on: add the inspiration locally
     AND publish to GitHub; on success, update the local record
     with the issue number / html_url.

3. **`/pool` tab** (new bottom-nav item, between `/my` and
   `/settings`):
   - Header: pool repo + "Sync now" + "Filter by tag ▾" + "Sort:
     newest / most-liked / mine".
   - List: each pool inspiration as a card with author /
     tags / reaction counts / my reaction toggle.
   - "Save to My Ideas" button: copies the pool inspiration to
     the local store as a fresh entry (with `origin: {number,
     owner, repo}` so the lineage is preserved).
   - "Open on GitHub" link: opens the issue in a new tab.

4. **`/graph` includes pool nodes**:
   - On mount, fetch pool cache (or pull a fresh copy from
     GitHub if the cache is > 1h old).
   - Pool nodes are rendered with a slightly different shape
     (ring around the dot) so they read as "not mine".
   - User's own pool publications get a small "↗" badge.
   - Cross-community edges: a pool inspiration is connected
     to a local inspiration if their TF-IDF cosine is > 0.25.
     This is the "graphify串一串" link the user mentioned.

5. **Reaction toggle on pool cards**: tap 👍 to like, 👎 to
   dislike, tap again to clear. Updates the local override map
   immediately for snappy UX, then fires the API call. On
   failure, revert.

6. **`/my` shows pool publications separately**:
   - The "My Ideas" list now has two sections: "Local only"
   (insights never published) and "Published to <repo>" (local
   copy has a `_poolOrigin` field). A small filter chip to
   toggle the visibility.

## Edge cases & limits

- **Empty Pool config**: the `/pool` tab shows a "Connect a
  GitHub pool to discover others' ideas" empty state with a
  button to `/settings#pool`. No GitHub API calls until then.
- **PAT invalid / expired**: the "Sync now" surfaces a friendly
  error toast and the Pool tab degrades to "last known cache"
  (or empty). Disconnect + reconnect required.
- **Rate limit**: 5000 req/hr for authenticated users. The
  publish path uses 1 req per inspiration; the poll path uses
  1 req per 100 inspirations (with `per_page=100`). Caching
  with a `lastSync` timestamp avoids burning quota.
- **Private pool**: the fetch path requires the token in the
  `Authorization` header to see issues. Still works.
- **CORS**: the GitHub API supports CORS for `api.github.com`
  with no special setup. Confirmed.
- **Token storage**: localStorage is plaintext. Acceptable
  for an MVP but document it. (v0.8 may add Web Crypto
  encryption with a user-supplied passphrase.)

## Routing decision

- The 5-tab bottom nav (Capture / Graph / Timeline / Pool / My)
  fits on a 360px viewport (5 × 60px = 300px, plus 60px padding
  for the safe areas).
- Use the `graphify` mental model for the cross-community edge
  detection: each pool inspiration + each local inspiration is
  a node; a TF-IDF cosine > 0.25 between any two creates an
  INFERRED edge. User-pinned (capture-time pin) → EXTRACTED
  edge. The legend distinguishes these in the graph view.
- No external LLM calls. Pure client TF-IDF. Same algorithm
  already in `insight-connections.js` — extend, don't rewrite.
